## 4. 识别方法与准确率

### 4.1 双通道设计

| 通道 | 做法 | 作用 |
|---|---|---|
| 底色 | 格内多点取众数颜色 → 最近调色板匹配 | 给出数值候选 |
| 字形 | 以该格底色为基准，取"亮度差 > 55"的墨迹 → 归一化 8×8 签名 → 与模板汉明距离比对 | 独立校验数值 |

**冲突即停**：若某数值已有模板、而字形强烈指向另一数值（距离 ≤ 4），标记 `Low`，运行器立即停止。

### 4.2 准确率如何验证

- **移动级验证**：每步用 `Verify-2048Transition` 把"操作前 + 方向"按规则推演，再与实际"操作后"比对，允许且仅允许 1 个新方块（2 或 4）。**30/30 全部通过。**
- **终局核对**：最终画面与引擎最后一次读数逐格目视一致（8/64/8/4 · 2/16/2 · 2）。
- **诚实说明**：由于没有独立 ground truth，"识别准确率"无法单独测量；只能说**30 次转移全部与规则自洽，且终局与画面一致，未发现可归因于识别的错误**。若前后两帧犯了同一个错，规则校验无法发现——这是该方法固有的盲区。

### 4.3 一个未能解释的偏差

引擎累计 `Gain` 为 **300** 分，而页面分数从 72 增至 376（+304）。**相差 4 分**。
可能原因：运行开始时的实际分数并非 72、或某次合并的计分与引擎模拟不完全一致。
**未查明，如实记录**，不编造解释。

## 8. 已知限制

1. **模板冷启动**：每次运行模板库为空，首次遇到 16/32/64 时只能依赖颜色（标记 High 但未经字形确认）。
2. **2/4 底色过近**（ΔRGB=23）：极端渲染条件下仍可能混淆，字形通道是补偿而非根治。
3. **得分对账差 4 分**：原因未明（见 4.3）。
4. **决策策略简单**：固定权重打分，无 lookahead；能跑 30 步，但长期不一定最优。
5. **执行策略依赖内存加载**：若目标机器策略不同，README 中的两段式加载需按环境调整。

### 1. 更正内容

§4.3 记载「引擎累计 `Gain` 为 **300** 分，而页面分数从 72 增至 376（+304）」。
其中 **300 是笔误**。

对原始运行 CSV 的 30 行棋盘转移逐条重放后：

| 量 | 值 | 性质 |
|---|---|---|
| 30 步理论合并得分合计 | **304** | 可复现计算（见第 4 节） |
| 终局页面分数 | **376** | 直接观测（截图 SCORE / BEST 均为 376） |
| 开局页面分数 | **Unknown** | 无运行开始时的截图 |
| 开局分数（反推） | 72 | **Inferred**（376 − 304），非观测值 |

**304 = 304**。本次差异可由报告中的手工求和笔误完整解释；**未发现运行时计分缺陷**。

### 2. 为什么会出现 300

原始 `run-*.csv` 的表头为：

```
round,time,dir,ret,changed,verify,valid,lowconf,board,beforeText,afterText,elapsedMs
```

**没有 Gain 字段，也没有累计分数**；`summary-*.json` 同样不含 Gain。
也就是说，任何"累计 Gain"都必须由 `beforeText` / `afterText` 按 2048 规则重放得出。
§4.3 的 300 不是机器输出，而是撰写报告时的人工求和结果——少加了一次 4 分合并。

### 3. 勘误：先前的"重开新局"判断作废

Issue #2 的初步调查中曾提出「POC-004b 结束最大方块为 64、POC-005 起始为 16，因此必然重开新局」。
**该判断错误，现予撤回。**

复核方式：用同一识别模块重新识别 POC-004b 的结束画面，得到棋盘

```
0 0 0 2
2 0 0 0
0 0 0 8
0 0 8 16
```

最大方块 **16**；与 POC-005 CSV 第 1 步 `beforeText` 的 16 个格子**逐格完全一致**。

| 项 | 值 |
|---|---|
| POC-004b 最终棋盘（像素重建） | `0 0 0 2 / 2 0 0 0 / 0 0 0 8 / 0 0 8 16` |
| POC-005 起始棋盘（CSV 第 1 行） | 同上 |
| 逐格比较 | **16 / 16 一致** |
| 是否发生重置 | **无证据支持；棋盘连续** |

先前得出"64"的原因：把 POC-005 的**终局**棋盘误当成了 POC-004b 的结束棋盘。
因此"基线被重置"这一说法**不成立**。

### 4. 复现方法

只读重放（不修改任何原始文件）：

1. 读 `run-*.csv` 每行的 `beforeText`、`dir`、`afterText`（16 个空格分隔整数）。
2. 按 2048 规则对该方向压缩并合并（同值相邻合并，得分 += 合并结果），得到 expected。
3. 断言 `afterText` == expected，且仅多出 1 个新方块（2 或 4，位于原空格）。
4. 累加每步得分即为理论累计 Gain。
