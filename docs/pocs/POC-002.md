## 1. 实验设计

### 1.1 分工

| 角色 | 职责 |
|---|---|
| Agent | 截图观察 → 识别场景/任务/NPC → 决策 → 输出单步指令 → 截图验证 |
| 用户 | 执行鼠标/键盘动作，回复「完成」 |

### 1.2 约束（全程遵守）

- 仅使用 POC-001 已验证的 `CopyFromScreen` + `read_image` 截图链路
- **不调用 `SendInput` / `SetCursorPos` 向游戏发送输入**
- 不提权、不装插件、不改游戏文件与系统安全设置
- 不读写账号密码；不交易、不充值、不删除物品
- 每次只给**一个**明确动作；不连续推进
- 状态不明时重新截图，不臆测
- 遇不可逆操作暂停征求同意

### 1.3 每轮循环

```
Observe（截图） → Think（读追踪面板/对话框/场景） → Act（单步指令）
      ↑                                                    ↓
      └──────── Verify（用户回「完成」后重新截图判定） ←────┘
```

### 2.1 任务状态的四次演进（核心证据链）

```
① 新手试炼：人族使者似乎有事找自己
        ↓（第 1–8 步对话与选择）
② 新手试炼：设置召唤兽参战，再与人族使者对话
        ↓（第 9–13 步打开面板并点参战）
   「参战」→「休息」，宠物血条出现（设置完成，但追踪未变）
        ↓（第 14–15 步交付）
③ 新手试炼：穿好武器与衣服，再与人族使者对话   ← 新节点，说明前一环已结算
```

**判定依据**：追踪面板文案的变化由游戏自身写入，而非我的推测——这是本次实验中最可靠的"客观事实源"。

### 2.2 关于"用户已执行"与"截图证明成功"的区分

- 用户每次都只回复「完成」，**从未描述画面**；
- 所有"成功"判定均来自我自己的截图分析，不采信"完成"二字；
- 15 次操作中，**15 次的截图都出现了可观测的状态变化**，无一次需要重试或纠正。

### 3.3 明显瓶颈

1. **窗口遮挡**：每次截图都要抢前台再还原，用户需反复 `Alt+Tab`——这是流程最大的摩擦点。
2. **坐标不可靠**：第 10 步我给的屏幕坐标 `(1624,1564)`，用户实际光标落在 `(1525,1923)`，偏差约 `(-99,+359)`。原因是 150% DPI 下窗口坐标与光标坐标系不一致。**幸好指令里写了画面描述**，用户按描述找到了图标。
3. **`.ps1` 被策略禁止**：本想固化截图脚本，被执行策略拦截（未修改该设置），只能继续内联执行。

## 4. 已确认事实 vs 未证明假设

### 4.1 已确认事实

1. 任务追踪面板的文案可作为**权威状态源**，且能被我稳定读取（含红字关键词区）。
2. 对话推进有两种有效交互：**点击正文区域**、**点击右下角按钮**；两者在本局都验证成功。
3. 对话框的「×」可正常关闭，关闭后世界画面恢复可操作。
4. 游戏 tooltip 是确认图标语义的可靠手段（「宠物(Alt+P)」）。
5. 「宠物」与「召唤兽」是两套面板，入口在宠物面板内的「召唤兽」按钮。
6. 「参战」按钮是**状态开关**：未参战时显示「参战」，参战后变「休息」。
7. 参战成功后，角色头像旁会出现**宠物血条**——第二个独立可验证信号。
8. 交任务成功后，任务追踪会立即改写为下一环目标。
9. 15 次操作全部产生预期类型的状态变化（100%）。

### 4.2 未证明 / 存疑

| 项 | 说明 |
|---|---|
| 第 4 步「‖」按钮的真实语义 | 我回避了它，改点正文；它究竟是"暂停自动播放"还是"继续"，**未验证** |
| 「大海龟 / 海星 / 海狸」的实际属性差异 | 界面不显示，我按"稳妥优先"选了海龟，**选择优劣未验证** |
| 任务追踪里并行的黄字「强盗宇文峰…」是什么 | 未探查，可能是另一条支线 |
| 交付后获得的武器/衣服是否已进背包 | 未打开背包确认（超出步数预算） |
| 坐标偏差的精确成因 | 只能确认"不可靠"，究竟是 DPI 虚拟化还是多屏坐标系，未做受控实验 |

## 5. 可复用的经验（对后续 Agent 设计最有价值的部分）

1. **任务追踪面板优先于画面理解**：与其从场景里猜下一步，不如直接读任务的当前目标文本 —— 它的更新由游戏保证，是判断"是否推进"的唯一硬标准。
2. **用 tooltip 做语义探针**：图标无文字时，先悬停读 tooltip，再决定是否点击。零风险、高信息量。
3. **"预期结果"要写成可观测的状态**：例如"任务追踪应变化"比"界面应该打开"更容易验证，也不容易被"看起来变了"骗过。
4. **区分'设置成功'与'任务完成'**：第 13 步参战按钮已变「休息」，但任务追踪没变——因为还要回去交付。这两件事必须分开判断。
5. **不可逆操作要单独停顿**：初始召唤兽是一次性选择，暂停询问是正确的；由用户授权后再执行。
6. **坐标永远配一句画面描述**：在 DPI 不确定的环境下，描述是主、坐标是辅。这次正是描述救了第 10 步。

## 7. 后续建议

| 优先级 | 建议 | 收益 |

| P0 | 把"任务追踪面板"做成每轮的**必读区域**（固定裁剪 + OCR 或视觉），作为状态机输入 | 大幅提升判定可靠性 |
